# Citation, provenance and derivative-instance policy

## Mandatory citation chain

Every instance-level record must resolve through this chain:

`instance_id -> dataset_id -> dataset version/DOI -> associated paper/data citation(s) -> parent dataset(s) -> licence/terms`

For derived benchmarks, cite both the paper that defines the new variant and the parent benchmark. Examples:

- Schneider E-VRPTW: cite Schneider, Stenger & Goeke (2014) and the exact Mendeley Data version used.
- Gradient-aware Schneider derivatives: cite the Rastani et al. dataset record/paper and Schneider et al. (2014) as parent data.
- Two-echelon EVRP: cite Akbay et al. (2022) for the method/problem formulation and Akbay & Blum (2025) for the expanded dataset release.
- EVRP-NL-C: cite Montoya et al. (2017) for the 120-instance base family and Froger et al. (2022) for charger-capacity constraints and the 240 derived variants.
- Mixed-fleet LEZ: cite the LEZ dataset and its paper, plus Schneider et al. (2014) where Schneider instances are the parent.

## Never conflate these quantities

1. A **dataset** is a named publication/release.
2. An **instance** is one problem file in a dataset release.
3. A **variant** is a defined change to the mathematical problem or instance attributes.
4. A **derived instance** is generated by a documented transformation of a parent instance.
5. A **local snapshot** is the exact archive/files downloaded or supplied to this repository.

For example, DIMACS describes 120 E-VRP-NL base instances and 240 E-VRP-NL-C capacity variants (one- and two-charger variants per base instance). Report these as 120 base + 240 derived = 360 category entries, not as 360 unrelated base instances.

## Required instance-level metadata

Each normalized instance should eventually carry:

- `instance_id`, `dataset_id`, `dataset_version`, `parent_instance_id` (nullable)
- `source_filename`, `source_url`, `retrieved_at_utc`, `sha256`
- `related_citation_ids`, `dataset_doi`, `licence_id`
- `transformation_id`, `transformation_parameters`, `transformation_code_version`
- `problem_family`, `supported_features`, `unsupported_features`
- `units` and `parameter provenance` (source-provided, derived, assumed)
- `validation_status` and `validation_report_ref`

## Citation examples

### Dataset with a DOI

> Goeke, D., & Schneider, M. (2022). *EVRPTW-MF* (Version 1) [Data set]. Mendeley Data. https://doi.org/10.17632/bd7rm5fw6k.1

Also cite the associated research article: Goeke, D., & Schneider, M. (2015). Routing a mixed fleet of electric and conventional vehicles. *European Journal of Operational Research*, 245(1), 81–99. https://doi.org/10.1016/j.ejor.2015.01.049

### Dataset without a separate DOI

Cite the dataset landing page/repository URL and its primary paper. Pin a Git commit or release tag and store the commit hash in the local snapshot manifest.

## Licence and redistribution policy

A public download link does not automatically permit redistribution. Store third-party datasets as external references by default. Vendor data only after checking the exact release licence and any attribution/non-commercial/share-alike conditions. The Schneider Mendeley record is CC BY-NC 3.0; this must not be treated as unrestricted commercial-use data.
